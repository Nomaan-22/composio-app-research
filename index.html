01 — The headline

APIs aren't usually
the bottleneck. Access is.

Across the 100-app dataset, API surfaces are widespread. The harder product-ops question is whether a developer can actually obtain credentials, satisfy permissions, and build reliably without an outreach-heavy process.

93% have documented REST surfaces, while 60% are classified as freely self-serve.

🟡 Conditional

The API exists, but permissions, commercial plans or onboarding requirements make implementation less straightforward.

🔴 Outreach

04 — Proof

The agent wasn't trusted blindly.

Automated validation and independent review answer different questions. The first measures evidence consistency; the second checks whether the research actually reflects the real documentation.

20-app independent sample selected across categories, access models, validation outcomes and repair histories.

✓ Confirmed — Slack

The agent classified Slack's Web API as non-REST; this is a useful example of a nuanced classification that survives independent documentation review.

⚠ Qualified — Jira

Core API findings were directionally correct, but authentication classifications require careful qualification across Jira app types.

✕ Caught — NotebookLM

Review surfaced an evidence-quality problem: unofficial/community NotebookLM tooling was too easily conflated with official or enterprise capabilities.

Automated result

93/100 passed the final evidence validator.

What verification adds

It catches weak source selection and semantic overreach that a mechanically consistent evidence link can still miss.

Honest failure mode

NotebookLM is retained as a cautionary example instead of being quietly corrected after the fact.

HOW IT WORKS

  
Research → evidence → validation → repair

  
The core idea is not one giant prompt. It is a repeatable evidence pipeline with checkpoints, targeted repair, and a human QA layer.

  

    

      
100-app assignmentApp name, website and category become structured targets.

      
OrchestratorRuns one app at a time, checkpoints results and resumes safely.

      
Research agentSearches auth, API surface, access model and MCP evidence.

      
Official sourcesDeveloper docs, API references, pricing/access pages and official GitHub.

    

    

      
Structured JSONAuth, self-serve, REST, GraphQL, MCP, buildability and evidence.

      
Evidence validatorChecks claims against fetched source content.

      
Targeted repairOnly failed claims trigger another research pass.

      
Checkpoint + analysisValidated app records feed the final matrix and pattern analysis.

    

    
FAIL → targeted repair → validate again

      This is the key quality loop. Stagnation guards stop repeated research when no new evidence is being found.

    

      Human verification: sample the output against real documentation, record hits/misses, and report limitations honestly.
